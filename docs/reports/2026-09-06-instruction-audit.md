## 建议与剩余边界

1. **先统一发布来源。** 当前仓库副本与外部安装副本并存。建议明确“仓库是维护源，安装副本是发布产物”，在单独授权的发布任务中对比、同步、验证再由 owner 决定是否锁 digest；不要直接编辑插件缓存或盲目重锁。
2. **渐进合并学科 reference 副本。** 98 个 references 中仍有 11 组内容完全相同，包括中英文语言指南、词汇表、模板、可行性与依赖参考。它们受模块 manifest/分发方式影响，本次保留路径；后续可在明确打包契约后改成共享源生成副本。不要仅为减少文件数直接删除。
3. **做小规模行为回归。** 用“局部改写、已授权完整草稿、贡献改变、只生成日报、扫描精读、外部写入响应不确定”六类任务比较停问次数、完成率、证据遗漏和实际成本，再决定是否继续压缩。当前只有静态与人工一致性证据，没有成本或质量提升的实测结论。
4. **保持业务细则按需加载。** 当前仍保留学科 gate、完整评审、版式和语言细则；本次没有为套用 Astra 而抹掉它们，也没有调整评分器或执行脚本。历史 C5.5 工具与检测相关实现仍需单独做能力评估，入口已明确不承诺检测器结果。
5. **检查会话外指令源。** 用户本轮注入的自动长任务/CodeGraph 规则、用户级技能和插件技能不属于仓库文件。本次根 AGENTS.md 不会覆盖更高层或本轮明确注入的指令；若要全局生效，应在单独明确范围后更新对应来源。
