## 想法池（价值 / 每次成本 / 依赖）

### A. 日常开发质量
- diff-review 轻量入口（只审本次 git diff，commit 前调用）｜高｜1 次/节点｜复用现有脚本
- 修复闭环（codex 审出 → 自出补丁 → CC 跑测试验收）｜高｜2 次/修复｜新 prompt 模板
- 测试生成（模块代码 → codex 写测试）｜中｜1 次/模块｜新模板
- 双实现对抗常态化（仅高风险改动）｜高｜贵｜已有脚本流程化

### B. 研究流程
- 雷达日报智能化（文献 → codex 总结+相关性排序，日报变简报）｜高｜1 次/天=30 次/月 ⚠ 超出按需节制，需费用单独点头｜雷达管线
- 论文解读（PDF→文本→结构化：方法/结论/与课题关系）｜高｜1 次/篇按需｜PDF 提取已有
- 实验方案提案（研究问题+约束 → codex 出方案，CC/用户裁决）｜中高｜1 次/方案｜新模板
- 论文 claim 核验（断言 vs 全文证据）｜中｜1 次/篇｜已有 claim-check 换输入

### C. 运维与巡检
- 日志巡检（broker/雷达日志 → 异常摘要，周频）｜中｜1 次/周｜sync 拉日志
- 面板截图解读（codex -i 图片入参）｜低（视觉验收用户人工）｜1 次/查｜无
- 系统诊断解读（事件摘要 → codex 判读）｜中｜低频按需｜无

### D. 文档与报告
- spec/验收报告初稿 → CC 校对定稿｜中｜1 次/文档｜新模板

### E. 横切基建（四领域都受益）
- **模型路由表**（task-type→model 映射，策略文件用户维护，CC 读表传 --model）｜高｜零新增｜表由用户填
- **resume 脚本化**（长会话续接：省冷启动 128s + 省上下文重传 = 省钱）｜高｜零｜能力已验证
- **usage 统计入账**（每次调用 token 消耗存档+汇总 → 费用可见）｜高｜零｜改 codex_exec
- **--output-schema 硬约束**（JSON Schema 替代 prompt 级契约）｜中高｜一次性改造｜能力已验证

## 三个落地方案（权衡与推荐）

1. **横切基建先行（推荐）**：路由表 + usage 统计 + resume。零/低新增成本，四领域受益；路由表回答用户点名问题；usage 让费用可见。适合 mission 028 小体量。
2. **开发质量深耕**：diff-review + 修复闭环，受益面仅 A 领域。
3. **雷达日报智能化**：价值直观（每天省 5 分钟），月 30 次调用需费用点头。

推荐顺序：方案一先行 → 路由表+usage 在手后，方案二/三可更便宜更聪明地推进（如日报用便宜模型跑总结）。
