# 并发工作模式约定（两档）

日期：2026-08-20
状态：标准档=已实战（mission 030）；树状档=参数定稿、首跑中（mission 031）

## 定位（用户设想，2026-08-19 定稿）

opus 只作为与用户对接的 agent：分析任务、拆解转派、收敛审查、汇总汇报、**统一 commit**。
原则上不亲自干执行活（≤3 文件的机械合并/编辑除外，须记 DECISIONS.md）。
agent 一律不 commit。

## 标准档（默认）

- **触发**：任务可拆成 2-8 个独立叶子；单文件或单子系统
- **结构**：根 opus → 叶子 ×≤8（haiku 默认；sonnet 仅视觉需求）
- **隔离**：叶子文件不重叠；同文件场景副本隔离（`D:\Temp\concurrent\<X>\`，改完产 diff 回流）
- **收敛**：根顺序合并 + 每步全量测试 → 独立验收 agent 审查合并 diff → 统一 commit → 汇报
- **实战**：mission 030（3 路并行，验收 fidelity 100%，broker 47→102 测试全绿）

## 树状档

- **触发**：任务可拆成 ≥2 个独立子系统、且每个子系统内 ≥3 个独立叶子；单层超过 8 路就分树
- **结构**：根 opus（只接口）→ 子协调者 opus ×≤3 → 叶子 ×≤4/子树（**总 ≤12**）
- **子协调者模型**：opus 子代理（fcc 路由 DeepSeek，便宜可控）；**交叉验证类子树用 codex**（三档路由查 `orchestra/config/model-routing.json`，冷启动 ~2min，--timeout ≥1800）
- **收敛链**：叶子 DONE → 子协调者收口子树（合并子树内 + 全量测试）→ 根派独立验收 agent 审子树 diff → 根统一 merge+commit+汇报
- **隔离**：子树间文件不重叠；同文件场景子树副本隔离（`D:\Temp\tree\<subtree>\`），两段式合并（子树内→子树间）
- **失败处理**：叶子 CONCERN×2 → 子协调者接管；子树 BLOCKED → 上抛根，重分派或降级扁平
- **派发机制**：子代理嵌套（Agent 工具可递归）。Workflow 工具为确定性扇出另案（需用户显式开启，适用机械扫描类，本次不启用）
- **交付与通信**：叶子的最终回复文本自动回父代理（嵌套 agent 不在 SendMessage 注册表，勿尝试 SendMessage 回执——031 实测三个叶子均遇此困惑，最终文本即交付物）；子树协调者收口后同样以最终文本回根
- **codex 叶子**：Windows 下 codex CLI 控制台 GBK 编码会打印崩溃（031 实测首跑崩、UTF-8 重跑 320s 成功），调用前设 UTF-8 环境

## 030 复盘教训

1. 隔离副本 + diff 回流比 agent 直改仓库可靠
2. 并发修复遇外部协作者大提交时"leaf 不重叠"失效——同文件双轨合并须人工定原则逐块裁决（实战模式："对方主体 + 保留我方增量"，见 a2d31b8 合并）
3. 测试按部署目标平台写（Pi=POSIX）；开发机 Windows 上的适配属测试层问题（bash 解析/路径斜杠/文件锁），勿为此改生产脚本语义
4. 验收与执行解耦是收敛质量的兜底：合并（机械操作）可直接执行，审查（独立判断）必须派 agent
5. mock 陷阱：autospec=True + 计数器委托真函数；side_effect 列表直接放函数引用会假绿
