# 执行、授权与验证

适用于本仓库 academic / nature 技能。入口定义业务目标，manifest 保留阶段与加载契约，references 仅在对应阶段读取。用户明确指令优先于流程默认值，技能不能扩大用户授权。

- 根据已有材料进入所需阶段，不因普通修订重跑完整流水线。常规工具、排版和措辞选择自行处理；用户选定的步进模式和业务确认点继续有效。
- 自动质量检查失败表示产物尚未满足条件，不等同于每次都要用户批准。先修复已授权的问题；涉及研究方向、贡献主张、原始数据解释或明确人工门禁时才请求决定。
- 用户已确认的范围与授权沿用。对外发送、投稿、定时任务创建/恢复、外部库写入及计算资源使用须有对应授权；本地准备可以先完成。保存的定时任务授权以其目标、收件人和范围为限。
- 工具按当前可用能力选择；文档中的模型、CLI、MCP 名称是路由提示，不证明已经安装或可调用。缺少某个技能不构成独立阻塞理由；寻找能保持输出契约的工具。
- 只读取本阶段所需材料。长任务在阶段结束记录已完成产物、未决问题和下一步，不重复已经完成的工作。
- 验证围绕改动及验收条件；完成后报告实际检查与结果。未运行的检查、未读取的全文和缺失的证据不能标为通过。保留 source map、引用核验、metrics schema、贡献确认与 digest 门禁。

写作辅助可以产出完整草稿；草稿不自动取得作者确认或投稿/提交授权。不得编造数据、引用、用户观点或把 planned 结果写成 verified。语言润色不承诺检测器分数，也不能替代证据核验。
