# Nature Data Availability (Embedded)

**Source:** `nature-data` | **Snapshot:** 2026-06-06
**Pipeline usage:** S10 (Submission Prep — 10B. Data Availability Statement)

## Default Stance
- Statement is a link between claims and the evidence to inspect/reproduce/reuse them
- Do NOT invent DOIs, accession numbers, repository names, or licenses
- Prefer public, discipline-specific repositories
- Describe both newly generated and reused third-party data
- If data cannot be shared: state why, who controls access, how to request

## FAIR Metadata Checklist
- **F**indable: DOI/Accession number, indexed in repository
- **A**ccessible: Open access or documented access process
- **I**nteroperable: Standard formats, controlled vocabularies
- **R**eusable: License, provenance, community standards

## Repository Selection
| Data Type | Recommended Repository |
|-----------|----------------------|
| Sequence data | NCBI GenBank/SRA, ENA |
| Structure data | PDB |
| Microarray/omics | GEO, ArrayExpress |
| Code | GitHub/Zenodo (with DOI) |
| General data | Figshare, Zenodo, Dryad |
| Surveys | OSF, ICPSR |

## Statement Templates
- **Open data:** "Data and code are available at [repository] under [license]."
- **Restricted:** "Data cannot be shared publicly due to [reason]. Researchers may request access via [process]."
- **No data (theory):** explain what IS available (code, parameters, proofs)
