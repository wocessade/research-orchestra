# Stage T1.5: 数据审计 [Strategist]

**Gate:** QT1.5 (CONDITIONAL BLOCK)
**Goal:** Assess data quality, structure, and fitness for the proposed research before literature review begins.
**Needs Composers:** none

## Decisions

### Axis 1: Conditional Activation
```
if hasData == true:
    → activate T1.5 data audit
    → proceed with full checklist below
elif hasData == false:
    → SKIP T1.5 entirely
    → set skip_reason = "no_data_provided"
    → proceed directly to T2
elif hasData == "unknown":
    → ask user: "Do you have a dataset for this thesis?"
    → branch on response
```

### Axis 2: Descriptive EDA Only (STRICT BOUNDARY)
```
[D1B — STRICT PROHIBITION]
EDA scope: descriptive statistics ONLY
    → column names, data types, missing values, basic distributions
    → summary statistics (mean, median, std, min, max for numeric columns)
    → value counts for categorical columns

Forbidden:
    → NO correlation analysis
    → NO hypothesis testing
    → NO predictive modeling
    → NO pattern discovery
    → NO inferential statistics

Boundary enforcement:
    if any output suggests inferential analysis:
        → discard and re-run with stricter constraints
```

### Axis 3: Unknown Columns/Types
```
if any column has name_type_confidence < 0.7:
    → NEED USER INPUT
    → present: column_name, sampled_values, inferred_type
    → ask: "What does this column represent?"
    → user response required before continuing
if any column type is ambiguous (e.g., numeric-coded categorical):
    → ask user to confirm type
```

### Axis 4: Data Quality Assessment
Evaluate and report:
- **Completeness**: missing value ratio per column; flag columns with >30% missing
- **Consistency**: check for contradictory values (e.g., date_start > date_end)
- **Uniqueness**: duplicate row detection; flag if >5% duplicates
- **Outlier presence**: flag extreme values without statistical testing (visual inspection only)
- **Method recommendations**: based on data structure, suggest (not mandate) compatible methodology families

```
if data_quality_flags:
    → report each flag with severity (low/medium/high)
    → recommend pre-processing steps
    → do NOT execute preprocessing (execution belongs to composer)
```

## Gate

### QT1.5 Gate Checklist
- [ ] Data activation decision made (active/skipped)
- [ ] Descriptive EDA completed without boundary violation
- [ ] All unknown columns resolved with user input
- [ ] Data quality assessment report generated
- [ ] Method recommendations noted for T3

### Gate Failure Route
```
if boundary violation detected in EDA output:
    → BLOCK — discard current run, restart with D1B constraints
    → flag [VIOLATION: D1B] in audit record
if unknown columns unresolved:
    → BLOCK — user input required
if data quality high-severity issues found:
    → WARNING — recommend cleanup before proceeding
    → user may override and continue
```
